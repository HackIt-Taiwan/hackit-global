# Residual dependency advisory assessment

Checked 2026-11-02 for the tested **Linux arm64** candidate, local image ID `sha256:21168cc2dd960082facdfb3eb1a5f15ae9f947e94148ed00f05d0199089ad545`. This is a targeted application-reachability assessment, not an exploit proof or a complete native-code call graph.

The unchanged Trivy report has **0 Critical, 0 High, 36 Medium, and 8 Low package/CVE rows**, representing **29 unique CVEs**. Five GCC-source CVEs repeat across four binary packages, accounting for 20 rows. Nothing was ignored, hidden, or suppressed. The official distroless tag still resolves to the pinned digest; current supported Debian trixie packages match the installed versions. No safe routine base/dependency upgrade was available.

**Severity is source-dependent.** [CVE-2026-19499](https://sourceware.org/git/?p=glibc.git;a=blob_plain;f=advisories/GLIBC-SA-2026-0017) has upstream CVSS 7.7 High, and [CVE-2026-84243](https://raw.githubusercontent.com/CVEProject/cvelistV5/main/cves/2026/84xxx/CVE-2026-84243.json) has upstream/CNA CVSS 7.0 High, while the scanner lists both Medium. The zero-High statement applies to the recorded scanner classification, not every authority. Their required application conditions are assessed below.

## Fix availability

The Debian trixie versions remain flagged without stable fixed versions: glibc `2.41-12+deb13u4`, GCC runtime/source packages `14.2.0-19`, and zlib `1:1.3.dfsg+really1.3.1-1+b1`. Many **upstream fixes already exist** and some are packaged in Debian testing/unstable. That differs from an available supported stable update. Replacing stable libraries with cross-release packages or deleting package metadata to change scanner totals is not the chosen remediation.

For the first four GCC findings below, patches change headers/templates that can be compiled into native binaries. Updating only the shared C++ library cannot be assumed to repair such instances; a suitable vendor binary/toolchain rebuild may be needed. No compiler or native-library rebuild was performed by this application audit.

## zlib: two Medium rows

| Advisory                                                                     | Fix and reachability assessment                                                                                                                                                                                                                                                                                                                                        |
| ---------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [CVE-2026-27171](https://security-tracker.debian.org/tracker/CVE-2026-27171) | CRC-combine nontermination is fixed upstream in 1.3.2 and Debian unstable from `1:1.3.dfsg+really1.3.2-1`; trixie remains unfixed. | [CVE-2026-85091](https://security-tracker.debian.org/tracker/CVE-2026-85091) | Nonblocking gzip-file formatted writes are fixed by an upstream commit and Debian unstable `1:1.3.dfsg+really1.3.2-4`; no stable fix found. The actual [Node 24.22.2 compression binding](https://github.com/nodejs/node/blob/v24.22.2/src/node_zlib.cc) uses deflate/inflate for gzip. The service prepares compressed variants only from trusted startup assets and subsequently selects cached bytes. The operating-system zlib findings are retained; they are not silently equated with Node's separately bundled implementation.

## Engineering disposition and remaining limits

No demonstrated visitor-to-vulnerable-operation path was found in the reviewed static service. It is reasonable to carry these **documented, monitored residual findings** for this candidate, without asserting that every native path is unreachable or every dependency is fixed. libc, libstdc++, and libgcc are genuinely loaded; the application bounds and container restrictions do not repair native memory corruption or make denial of service impossible.

Keep the raw findings visible and refresh/rebuild/rescan the maintained base when supported fixes arrive. Reassess after native addons, uploads, visitor-controlled regex/allocation/conversion/compression, commands, writable runtime content, environment trust changes, or a platform/architecture change. No application/base changes were made solely to alter scanner counts; no unrelated regression suites were repeated for this documentation-only assessment.
